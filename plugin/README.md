# ZCode 自动续跑

本地 ZCode 插件：检查最近 20 分钟仍有对话活动的任务，在速率限制或可重试的模型请求失败后，通过 ZCode 桌面窗口向原会话发送继续指令。任务创建时间不影响检查范围。

## 安装

需要 macOS、支持插件侧栏面板的 ZCode 桌面版、Python 3、Node.js 20+ 和授予 `osascript`/System Events 的辅助功能权限。发送时会短暂切换窗口焦点。仓库已包含构建产物，安装时不需要执行 npm install。

1. 克隆本仓库到本机。
2. 在 ZCode 的 **设置 → 插件管理 → 插件市场 → 添加** 中，将克隆目录添加为本地市场，安装并启用 `zcode-auto-resume`。
3. 在 ZCode 会话右上角展开侧边面板，选择 **新增标签 → 浏览器**，输入 `http://127.0.0.1:8765/`，即可在 ZCode 内使用监控页面。点击“开始检测”开启巡检。

插件还声明了官方 MCP App 面板和 `get_monitor_status` 工具，可让 ZCode“调用 get_monitor_status 打开自动续跑监控面板”。当前 ZCode 的侧栏首页仅展示推荐应用，自定义面板不会自动出现在推荐列表。已实测内置浏览器的显示与开关；MCP 安装包通信已通过自动化测试，尚未在真实会话中完成工具触发打开的验证。

如果 8765 端口已被占用，实际端口记录在 `~/.zcode/auto-resume/dashboard.port`。更新源码后，在 ZCode 中刷新本地市场并更新插件。

## 运行规则

- 检测默认停止；开始后立即巡检，此后每 2 分钟巡检一次。“停止”会取消后续巡检，刷新或关闭页面不会改变开关；页面服务重启后恢复为停止状态。
- 仅处理最近 20 分钟有消息、已静止至少 2 分钟、且最后一条错误符合重试条件的会话。运行中、正常结束、用户取消及参数错误不会自动续跑。
- 发送前检查侧栏中的唯一标题、会话主标题、空输入框和可用的发送按钮。粘贴并核对完整指令后，通过输入框提交键发送；只有原会话数据库出现同样的用户消息，才标记“已确认送达”。送达不保证模型随后执行成功。
- 同一条成功送达的错误消息只处理一次；同一任务尝试间隔至少 2 分钟，每天最多 100 次。未确认送达时自动停止检测，避免反复留下草稿。

面板默认显示检测开关、上次检查时间和最近 3 条续跑记录；本轮会话和巡检历史可展开查看。侧栏与网页共用同一个检测进程和计数，所有会话面板的开关同步。侧栏跟随 ZCode 的明暗主题，通过官方 MCP App 接口工作，不修改客户端文件。

日志、重试状态及巡检历史存放在 `~/.zcode/auto-resume/`；这些本地运行数据不随插件上传。页面历史最多保留 50 条续跑记录和 30 轮巡检，简版界面只展示其中最近的记录。

## 开发

`monitor.py` 负责巡检和本地服务，`desktop_send.applescript` 负责桌面提交。`src/` 是侧栏与本地服务之间的 MCP 服务，`ui/` 是网页和侧栏共用的界面源码。

运行 `npm ci && npm run check` 安装开发依赖、构建并测试；`npm run build` 将独立可运行的文件打包到 `plugin/`，市场只安装该目录。修改后需重新构建，并同步更新插件清单、市场和 package.json 中的版本。第三方依赖声明随构建写入 `plugin/dist/THIRD_PARTY_NOTICES.txt`。

手动查看候选任务：`python3 monitor.py once --dry-run`。仅运行巡检测试：`python3 -m unittest discover -s tests`。桌面自动化依赖当前 ZCode 的中文界面和本地数据库结构，客户端升级后需要重新验证兼容性。
